# Signature Magic

마법사 길드 등록부터 시그니처 마법 설계까지 이어지는 웹 기반 캐릭터 빌드 게임입니다. 타이틀에서 전체 이야기를 진행하는 CYOA 모드와 마법 조합만 독립적으로 사용하는 메타 모드를 선택할 수 있습니다.

플레이어는 CYOA 방식으로 마법사의 배경과 특성을 정하고, 단위 마법 노드를 연결해 자신만의 술식을 구성합니다. 선택한 특성은 마법 스탯에 반영되며, 완성된 조합은 마법진과 등록 결과로 시각화됩니다.

> 현재 개발 중인 프로젝트입니다.

이 프로젝트의 핵심 기술 목표는 **유지보수성**입니다. 기능을 빠르게 추가하는 것보다 기존 동작을 안전하게 이해하고, 작은 변경이 불필요하게 여러 영역으로 퍼지지 않는 구조를 우선합니다.

## 게임 흐름

타이틀에서 두 가지 진행 방식을 선택합니다.

- **CYOA 모드:** 길드 접수 대화 → 캐릭터 등록 → 조합 안내 → 마법 조합 → 길드 평가로 이어집니다. CYOA 선택의 스탯 보정과 최대 마나 제한을 사용합니다.
- **메타 모드:** 마법 조합 → 이름·설명 기록 → 마법 요약으로 바로 이어집니다. 별도의 마법진 전환 연출 없이 편집기 위 모달에서 그래프, 서클 문양, 최종 스탯을 확인하고 PNG로 내보낼 수 있습니다.

각 모드의 첫 화면에서 타이틀로 돌아갈 수 있습니다. 타이틀로 돌아가는 것만으로 작업은 지워지지 않지만, 모드를 다시 선택하면 새 게임으로 초기화됩니다. 브라우저에 저장한 사용자 프리셋은 유지됩니다.

## 주요 기능

### 캐릭터 등록 CYOA

- 필수 선택, 다중 선택, 조건부 표시를 지원하는 등록 항목
- 일반 선택지와 하위 선택지를 조합하는 중첩 선택 구조
- 캐릭터 이름과 서명 등 텍스트 입력
- 선택 결과에 따른 노드별·최종 마법 스탯 보정
- 제출 전 등록 신청서 검토

### 마법 노드 편집기

- 속성, 행동, 조절, 제어 카테고리로 구성된 단위 마법
- 클릭 또는 드래그 앤 드롭을 통한 노드 배치
- 입력·출력 제한과 순환 규칙을 반영한 연결 검증
- 정방향 분기와 서클 간 연결을 이용한 흐름 구성
- 반복 노드를 이용한 1~99회 반복 조합
- 노드 메모, 커스텀 이름, 반복 횟수 편집
- 기본 프리셋과 브라우저에 저장되는 사용자 프리셋
- CYOA에서 결정되는 최대 마나와 마나 소모 제한

### 마법진과 결과

- 유효한 마법 경로를 서클 단위로 실시간 분석
- 노드 구성에 따라 생성되는 마법진과 글리프
- 시전 시간, 불안정성, 출력, 범위, 마나 소모, 지속 시간 계산
- 내부 직렬 시퀀스·반복과 서클 간 병렬 구조를 반영한 최종 스탯 집계
- 시그니처 마법 전환 연출과 결과별 NPC 반응
- 등록 신청서, 마법 조합, 마법진을 포함한 PNG 내보내기
- 메타 모드의 마법 전용 요약과 PNG 내보내기

마법 편집 시스템의 자세한 사용법은 [인게임 가이드](public/magic-editor-guide.html)에서 확인할 수 있습니다.

## 실행 방법

### 요구 사항

- Node.js `^20.19.0` 또는 `>=22.12.0`
- npm

### 개발 서버

```bash
npm install
npm run dev
```

터미널에 표시되는 로컬 주소를 브라우저에서 열면 됩니다. 개발 환경에서는 화면 상단의 단계 이동 도구를 사용해 각 게임 화면으로 바로 이동할 수 있습니다.

### 프로덕션 빌드

```bash
npm run build
npm run preview
```

빌드 결과는 `dist/`에 생성됩니다. 빌드 전에 데이터 검증이 자동으로 실행됩니다.

## 유지보수성 중심 설계

코드는 변경 이유가 다른 책임을 분리하고, 각 기능의 영향 범위를 예측할 수 있도록 구성합니다.

- **UI와 도메인 로직 분리:** `components/`는 렌더링과 사용자 상호작용을 담당하고, 계산·검증·변환 정책은 `systems/`에 둡니다.
- **얇은 상태 저장소:** `stores/`는 상태와 도메인 기능을 연결하며, 복잡한 규칙을 직접 소유하지 않습니다.
- **데이터 기반 콘텐츠:** 선택지, 대화, 단위 마법, 스탯 규칙과 프리셋을 JSON으로 관리해 콘텐츠 변경이 UI 코드 수정으로 번지지 않게 합니다.
- **명시적인 계약:** UI 문구, 식별자, 제한값과 공유 설정은 `constants/`와 타입으로 관리합니다.
- **순수 계산 우선:** 그래프 분석과 스탯 계산은 UI와 분리된 함수로 구현해 독립적으로 테스트할 수 있게 합니다.
- **변경 지점 가까이의 테스트:** 테스트를 대상 코드와 같은 디렉터리에 두어 수정 시 함께 찾아보고 갱신하기 쉽게 합니다.
- **빌드 전 데이터 검증:** 잘못된 참조와 누락된 설정을 실행 중이 아니라 검증 단계에서 발견합니다.

새로운 추상화는 현재의 중복이나 변경 비용을 실제로 줄일 때만 도입합니다. 확장 가능성만을 위한 범용 계층보다 단순하고 일관된 구조를 우선합니다.

## 프로젝트 구조

```text
.
├─ public/
│  └─ magic-editor-guide.html   # 인게임에서 새 탭으로 여는 상세 가이드
├─ src/
│  ├─ assets/                   # 캐릭터와 선택지 이미지
│  ├─ components/               # 화면과 UI 상호작용
│  │  ├─ app/                   # 단계 이동과 앱 공통 UI
│  │  ├─ cyoa/                  # 등록 CYOA와 대화
│  │  ├─ node-editor/           # 마법 노드 편집기와 마법진
│  │  ├─ registration/          # 등록 검토와 최종 결과
│  │  └─ shared/                # 도메인 간 공용 UI
│  ├─ constants/                # UI 계약과 도메인 설정값
│  ├─ data/                     # 콘텐츠와 계산 규칙 JSON
│  ├─ stores/                   # Svelte 상태 라우터
│  ├─ systems/                  # 계산, 검증, 변환 등 도메인 로직
│  ├─ types/                    # 공유 타입
│  └─ App.svelte                # 게임 단계별 화면 조합
└─ package.json
```

## 책임 경계와 데이터 흐름

```text
타이틀 모드 선택
  → appStore의 모드별 화면 순서
  → CYOA: choiceStore 보정·최대 마나 → graphStore → 길드 평가와 등록 결과
  → 메타: 빈 보정 → graphStore → 마법 전용 요약
```

- `stores/`는 화면에서 사용할 상태를 연결합니다.
- 도메인 규칙과 계산 정책은 `systems/`가 담당합니다.
- `components/`는 렌더링과 사용자 상호작용에 집중합니다.
- 데이터와 UI에서 함께 사용하는 계약은 `constants/`에 둡니다.

## 콘텐츠 데이터 수정

| 파일 | 책임 |
| --- | --- |
| `src/data/cyoaRows.json` | 등록 항목, 선택지, 조건부 표시, 스탯·최대 마나 효과 |
| `src/data/cyoaDialogueScripts.json` | NPC 대화, 선택형 대사, 결과 조건 |
| `src/data/magicTypes.json` | 단위 마법의 이름, 설명, 카테고리, 스탯과 연결 규칙 |
| `src/data/magicStatRules.json` | 스탯별 직렬·분기·반복 집계 규칙 |
| `src/data/magicGraphPresets.json` | 게임에 포함되는 기본 마법 조합 |
| `src/data/magicGlyphs.json` | 단위 마법과 마법진 글리프 연결 |
| `src/data/magicGlyphShapes.json` | 글리프를 구성하는 벡터 도형 |

데이터를 수정한 뒤에는 반드시 다음 명령을 실행합니다.

```bash
npm run validate:data
```

검증기는 중복 ID, 잘못된 참조, 누락된 설정, 허용되지 않은 값과 연결 관계를 검사합니다.

## 검증 권장 순서

```bash
npm run validate:data
npm run check
npm test
npm run build
```

작은 변경은 관련 테스트부터 실행한 뒤, 완료 전에 영향 범위에 맞춰 전체 검증을 수행합니다.
